# math-markdown-pdf-polisher：按需执行细则

以下章节从本技能 SKILL.md 原样迁移。文中的 `references/`、`scripts/`、`assets/` 相对路径均以技能根目录（包含 SKILL.md 的目录）为基准；绝对路径及示例占位符保持原义。按 SKILL.md 的触发条件读取对应章节。

## 常见误区

- 以为 HTML 生成成功就代表 PDF 成功。
- 因为 HTML 容易出 PDF，就跳过 LaTeX 路线。
- 把 raw MinerU OCR 加 CSS 当成精排 PDF；如果 Markdown 没有语义清理，技术审计通过也不算。
- 凭感觉换公式渲染器，而不是保留用户确认的基线并比较缩略图。
- 最终离线交付还依赖 CDN MathJax。
- 用 Chrome CLI 默认打印，导致日期、路径、页码污染讲义。
- 让 OCR 图片文件名显示成 caption。
- `解析版` 仍把答案集中在末尾。
- 教师版把“题目 + 长答案”整块强制不分页，造成大空白。
- OCR 把小问、序号、选项粘成一堵文字墙却不整理。
- 只修 CSS 不修 Markdown 语义，导致裸变量、几何对象和函数名仍按正文字体渲染。
- 把题干公式留在 `##` 标题里，造成视觉层级和数学字体同时出问题。
- 成对图的 `图一/图二` 标签和图片分离。
- 为答案块全局加粗，导致 MathJax 分式过重；只加粗 `答案：`、`解析：` 等标签。
- 不核对上下文就重写可疑数学内容。
- 声称数学完全正确，但只做了抽查。
- 用户要求去水印时，拒绝去水印部分，可提供 OCR、裁边、压缩、分页等安全替代。
