# 输入与检查边界

## 教师分类汇编 Markdown

自动适配以下结构：

```markdown
### 分类名称
##### N01-Q03｜学校第3题 · 填空题
[原卷第3题](<原卷.md#q3>)
###### 原题与原成品内容
完整题目……
###### 本题分析
教师内容……
```

每个五级标题必须有分类、原题栏目和原卷链接。题干只取“原题与原成品内容”至下一六级栏目；缺项或题号重复就停止。题型从五级题目标题中的“填空题/选择题/解答题”提取，缺失时在分层标注中补充。小主题保持首次出现顺序，主题内按题型、难度分组后连续编号，同组保持原题序。

删除原题栏目中以“校订提示”或“编者注”开头的整段 Markdown 引用，保留其他引用（可能属于原题）。删除 Markdown 图片、Obsidian 嵌图和 HTML 图片标签，逐项记入台账。遇到未识别的图片写法、HTML、来源标签或答案栏目残留就停止，人工适配后再运行。

## 已核对的结构化输入 JSON

用于其他原稿格式；先按原文建立 JSON，不能把答案混入 `stem`。`source` 可以是包含链接、文件路径、原题号的对象；不会输出到 PDF。

```json
{
  "title": "不等式",
  "questions": [
    {
      "id": "Q001",
      "category": "性质与比较",
      "stem": "若 $a<b<0$，比较 $ab$ 与 $b^2$。",
      "question_type": "填空题",
      "difficulty": "基础题",
      "difficulty_basis": "教学预估：由负数乘法的不等号变向可直接判断。",
      "source": {"file": "原卷.md", "number": 3}
    }
  ]
}
```

要求 `id` 非空且唯一，`category` 和 `stem` 非空，`source` 提供必要追溯。题型只能为“填空题、选择题、填选题、解答题”；前三者输出时合并为“填选题”。难度只能为“基础题、中档题、难题”，依据必须非空。原来没有分层字段的 JSON 也须补齐或通过 `--classification` 提供。

## 内部分层标注

执行 agent 按 SKILL.md 的标准逐题判断，生成按原题 ID 索引的 JSON。此文件保存在任务工作区，不能写进学生版正文，也不自动沿用原卷题号猜难度。

```json
{
  "N01-Q03": {
    "question_type": "填空题",
    "difficulty": "中档题",
    "difficulty_basis": "教学预估：须将目标式转换为两个已知约束的线性组合，再处理系数符号及端点。"
  }
}
```

`--classification` 可以补充或覆盖输入的三个分层字段；出现不存在的题目 ID 会停止，遗漏必需字段时列出对应 ID。脚本只校验和排序，不凭正则计算难度；教学判断及其复核由执行 agent 完成。未审核的原稿难度标签应先核对，而非直接当成实测结论。

一个小主题的输出示例（只显示非空分组）：

```markdown
## 性质与比较
### 填选题 · 基础题
题目……
### 填选题 · 中档题
题目……
### 填选题 · 难题
题目……
### 解答题 · 基础题
题目……
### 解答题 · 中档题
题目……
### 解答题 · 难题
题目……
```

不新增单题难度徽章或分析文字。台账保留原题型、难度、依据、原顺序、新题号和各分组数量。

## 自动核验与人工核验

- 自动：源稿及分层标注哈希不变、分层字段合法、题号与分层台账一致、KaTeX 渲染数、无渲染错误、无图片/额外 HTML、A4、字框在版心内、没有题块跨页、题间与分组标题间实际净距、小主题和分组标题与首题同页、没有未归属文字、交付 PDF 无链接。
- 来源不泄漏以受控内容生成与抽取台账为主。脚本额外检查来源字段/教师栏目标记，但不能用“答案”单词全局禁用，辨错题可能合法含有该词。
- 人工：逐题源稿对照、去掉的内容是否确为编者资料、图依赖的影响、公式和小问视觉完整性、是否出现异常稀疏页。自动检查不证明数学正确，也不证明工作台匹配成功。
- 题号文本只用于检查标记和顺序，不以全文出现的数字或“第 N 题”次数推算题数。

## 本机依赖定位

默认引擎位于 `~/.workbuddy/skills/math-handout-pdf/scripts/build-prose-pretty.py`，可用 `--engine` 覆盖；不复制、不改写该引擎。引擎必须提供 `MINIMAL`、`tag_classes` 和 `main`，以及 `--no-page-number` 参数。

Node 可通过引擎支持的 `MATH_HANDOUT_NODE` 环境变量指定。依赖目录必须同时含 `katex` 和 `markdown-it`；可用 `--modules` 或 `XDF_STUDENT_NODE_MODULES` 指定。优先检查当前任务已有构建目录，避免在技能中固定某份题集的绝对依赖路径。

Chrome 默认用引擎的路径，也可通过 `--chrome` 覆盖。生成脚本不调用上传接口或外部网址；核验链接使用保留域名 `.invalid`，并在交付前移除。

旧引擎的通用检查曾要求至少两页，新脚本仅在当前进程中替换该检查，接受有效单页；随后使用自身题块归属、A4、字号、防缩放、实际净距和跨页检查验收。不修改全局引擎，不添加空页绕过检查。
