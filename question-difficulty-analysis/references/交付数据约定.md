# 交付数据约定

评分规则 HCT-rules-v1.1；封装 v1.1.1；计算引擎 0.1.2。详见 `examples/delivery-example.json`：这是自编格式示例，不是原卷评分锚点。

## 两个入口的区别

- `scripts/score.py` 是轻量计算器，兼容外部原版样例。返回计算结果及 `input_snapshot`，不能证明原题正确、阶段完整或证据真实。输入快照中的历史分数仅作原始记录，本次计算以顶层结果为准。
- `scripts/export_report.py` 是正式交付入口：先核对来源字段、阶段归属、类型引用、版本参数与清单，再生成证据完整的 JSON、小问 CSV、类型词典。每次使用新的输出目录。教师报告仍须 AI 另行撰写，程序不自动解题。

依次运行：

```sh
python /实际skill目录/scripts/score.py 输入.json --output 复算结果.json
python /实际skill目录/scripts/export_report.py 输入.json --out 本次交付目录
```

## 输入约定

根对象包含：

- `analysis_id`：本次分析标识，非空。
- `scope`：`question` 单题（含多小问）、`group` 同一来源提供的题组、`paper` 一整卷。不得因数组含两问就称整卷。
- `paper_id`：整卷必填；来源不明的单题可为 null，不造年份或卷名。
- `source`：原文件及版本定位，不仅写“来自试卷”。
- `algorithm`：固定 `HCT-rules-v1.1`。
- `parameter_version`、`dictionary_version`：非空版本；`parameters` 使用样例中的实际参数。当前引擎是固定规则计算器，不支持改权重；自定义参数会明确拒绝。修改参数需同步实现、验证并更换版本。
- `step_types`：类型字典条目；每条包含 id、name、definition、include、exclude、aliases 数组、status（如“本次临时词典”或“已复核”）。不能因字段齐全就宣称词典经教研验证。
- `questions`：按原卷顺序；包括无法评分的小问，不能只留已完成题。
- `expected_question_ids`、`inventory_source`：整卷必填。从原卷清点所有小问得到预期清单，说明清点来源；程序检查清单与记录一致，但其真实性仍须回到原卷核验。

每问沿用原版字段 id、score（考试分值或 null）、steps、t、T_evidence、B、B_evidence、branches。增加：

- `source_ref`：页码/题号/行号等来源定位；`verification_status`。
- `pending: true` 的单元保留 `issue` 原因，结果为 null。确定定分只允许 `verification_status: 已核验`；证据不足时转 pending，不补猜测评分。
- `solution_basis`：主解法选择与必要修订依据。
- `goal_phases`：每项有 id、type_id、name、goal、direction、output、step_ids。每一步恰属一个主阶段，无遗漏、重复或悬空引用。阶段本身不计分。
- 每个 step 增加 `phase_id` 和 `source_ref`；保留 input/action/output、dependencies、type_id、dimensions、dimension_evidence、commentary。依赖只表示前提，不能用线性排列替代必做平行分支。
- 机械重复使用 `repeat_group` 与 `repeat_evidence`。旧样例中的 `repetition_discount` 不是计算输入，不能靠填写这个字段修改折扣。

B沿用整数0—3和文本`B_evidence`，不增改计算字段；证据宜说明题面信号、关键动作、步骤定位和门槛依据，必要时写明回顾性入口分析及替代路径限制，见[B判定与使用](B判定与使用.md)。B未知时按现有待核口径处理，不伪填0。

每个维度与 T/B 分值均需具体数学依据。程序只能验证文本存在，无法验证这段话是否足够支持分值，人工或独立 AI 复核仍需阅读原题。

## 输出与跨卷

`评分明细.json` 中每问使用 `evidence` 保留原始输入，`computed` 存本次重新计算的结果；不混淆旧分数。CSV 未知值为空；不填 0。

先逐卷独立导出，再按 `(paper_id, question.id)` 定位小问；跨卷同名步骤按类型统计实例数、小问数、试卷数。算法、实际参数、词典须兼容；相同版本名也应核对实际内容。重复原题保留重复组及去重口径。当前程序不提供自动跨卷去重、词典语义合并或跨卷统计；这些需 AI 有证据地另做，不把多卷数组伪装成一卷。

原包三个旧样例保留作为计算兼容样例；其中历史来源和旧评分不被视为当前审题结论。正式交付样例单独维护。

从 `examples/blank-input.json` 起步可避免照搬示例分数。它保留实际参数，其他必填项须依据原卷填完；空白模板本身不能直接导出。目标阶段的 type_id 属于目标分类命名空间，不能拿步骤类型词典替代；当前只核验阶段成员关系，阶段类型语义由 AI 复核并在报告中说明。
