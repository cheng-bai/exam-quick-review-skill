# 试卷洞见与分类汇编

负责教研流程编排、跨题比较与教学判断，复用已有 OCR、数学审校和排版能力。成功标准是：每条洞见能回到原题，每个类别能解释同练价值，每册能核对母集与版本，修改后只重建受影响的成品。只生成当次授权的产品，不把完整成果包当作每次默认任务。

## 按需读取

- 同一年级多套卷子，要求先单卷逐题分析再形成分类汇编：读[年级多卷汇编流程](references/年级多卷汇编流程.md)，按[任务模板](templates/年级多卷任务模板.md)锁定范围；[虚构批次示例](examples/虚构批次流程示例.md)只用于理解流程，不是新批次答案。
- PDF到成果包、重跑、拆册、多版本或断点续作：先读[低返工执行流程](references/低返工执行流程.md)（`references/低返工执行流程.md`），确定本次模式、产物合同和当前可复用阶段。
- 考情报告、跨卷结构/趋势/学校差异与教学决策：读[考情报告合同](references/考情报告合同.md)（`references/考情报告合同.md`）。报告展开原题证据；汇编前言只给选题与使用结论，两者不共用正文合同。
- 分类定稿后制作汇编前言/简版考情说明/统计图：读[汇编说明与统计合同](references/汇编说明与统计合同.md)（`references/汇编说明与统计合同.md`）。只要简版前言不套完整图包；只评估框架时不自动制作PDF、图或ZIP。
- 开始分析：读取[洞见规则](references/洞见规则.md)（`references/洞见规则.md`）。
- 建立题目记录或交接：读取[交接与产物模板](references/交接与产物模板.md)（`references/交接与产物模板.md`），JSON 示例见[计数夹具](examples/counting-fixture.json)。
- 使用其他技能：读取[技能协作](references/技能协作.md)（`references/技能协作.md`），只加载当前阶段实际需要的技能。
- 维护或回归：读取[验收案例](references/验收案例.md)（`references/验收案例.md`）。案例是边界测试，不是新试卷的预设目录。

## 执行流程

1. **锁定本批范围与产品合同。** 从资料提取卷名、年级、学年、考试阶段、母集和输出位置，并从上下文确定产品用途与目标学生；缺失且影响范围时才询问。工程目录日期不当作考试年份。同卷扫描、OCR、学生/教师稿映射同一规范卷；不把联考展开成多份独立卷。区分考情报告、分类重建、拆册、只导出、汇编前言；只处理指定材料，不扩大到全库或网络。报告与选编分别冻结统计集合，不用入选题分布反推整卷结构。保留原件与用户修改。
2. **准备可核验原题底稿。** 先检查已有可信转录、解析、来源映射和校订，未变化输入不重复OCR。完整大题用稳定ID，不随分册、题序或改名变化；全部小问、选项、必要图与源解析保留。讲义配置引用底稿ID与修订版本，不各自维护题干副本。存在识别歧义时回看原材料，不猜补。识别、题意、答案、分类和成品状态分开。
3. **取得数学证据。** 已有解析默认保留原文，只作题意/结论一致性、关键链与边界的针对性检查；不为汇编或“已核验”标签逐题独立重算。缺解析、有明确错误/论证缺口，或用户明确要求时才调用审校/补解并重算受影响小问。记录每个小问关键入口、推进动作与适用边界。题意已核验但答案冲突的任务可用于任务分类和明确标注的频率，不作已核验评分题；题意不清的单元暂不计频。完整解答与关键链不得互相冒充。
4. **比较并形成分类。** 采用“专题→数学题型→题目形式→难度梯度”，知识对象、任务/方法、形式分别存储，关键动作与边界写入导读。分类地图、正文、统计和目录共用映射。用跨题比较与反例检验分类；每类说明共同结构、识别依据、处理路线和条件变化。单题技巧默认回题旁，独立成类须有教学理由并注明样本有限。先验证新分类的代表样板，通过后再全量；常规已确认规则无需每批再次等用户批准。交叉机制可建引用或按授权重现，计数用集合并集，不把类别行直接相加。
5. **提出可检验洞见。** 每条依次给出判断、完整原题及源解析、共同机制与差异、适用边界、教学动作，同时保留准确来源跳转。关键步骤强调直接附在原步骤旁，不重新改写整份解析。跨题共性需至少两道独立来源题支持；同题不同版本、同一道大题的多次展示不能充当独立证据。单题发现标为局部观察；跨校结论需至少两校，跨年结论需实际跨年且口径兼容。
6. **冻结并生成授权成品。** 冻结底稿修订、题目集合、主分类、版本内容合同与题序，再交给汇编/双版技能。每次拆册声明母集ID、覆盖模式和未收录/待核去向；仅要求并集覆盖不擅自要求两册互斥。按请求制作汇编说明时，来源与难度数据从编题阶段记录，说明在分类冻结后写。频率、先备关系、迁移价值和课时成本分开评价。发现错误回到底稿修订，按依赖重建受影响产品，不逐文件补丁或无差别全量重跑。
7. **检查并交付。** 用下方工具复算结构化记录，核对完整题干、图片、源定位、双版同序与答案隔离；安排可用且获准的独立复核，修复确认问题。报告已核验范围和未验证事项。

## 分类粒度与阅读呈现

- “题型”指具体数学任务与解题机制，如“区间补集与端点取舍”“含参二次不等式根序与降次”；选择、填空、解答只是题目形式，不能替代分类。
- 专题包含不同所求对象、转化或边界时按教学价值区分；同一机制仅数值不同不另立类。每类能解释为何同练、何处要换方法；不固定类数或单组题数。题型内再按题目形式和有依据的难度组织。
- 索引、正文分组标题、PDF目录与书签共享分类映射，不能只在台账写细类，正文仍连续堆题。目录可定位分类标题和首题。
- 本地分类汇编默认拆出大板块分册，保留整册入口；题目标题用五级、题内栏目六级，按实际长文结构调整。PDF题目采用紧凑序号来源行。
- 完整大题默认只归档一次，跨类小问在相应类别建引用，保留小问依赖。用户要求重复展示时可重现，展示次数与去重大题数分别统计。

## 按投入分层与导航

- 简单常规题：归类、原题/源答案解析汇总及必要格式检查，不逐题写长分析、不启动独立重算。
- 代表或边界题：沿用源解析，补关键步骤标记、简短方法概括、适用边界与教学动作；数学检查聚焦实际疑点。
- 解析缺漏/冲突题：明确触发原因，仅对受影响部分补证或重算，保留源解析并列勘误，不静默替换；完整重写只在原解析不够用或用户要求时做。

全量内嵌汇编保留完整源题块：全部小问、图片、本题分析、参考答案、参考解析与来源跳转；代表练习双版是选题产物，不能冒充全量版。每个交付Markdown有返回阅读入口；长文件首部有明确锚点大纲，大纲按板块/分类或卷题分层。纯题目学生版不得直链含答案的源解析或内嵌教师内容；用户授权的含本题分析版按内容合同保留原分析。数学定界用 `$…$` / `$$…$$`，显示修复不猜题意。

## 默认输出与工具

默认 Markdown：分层分类地图、完整源题块汇编、重点教研洞见、来源索引、统计 JSON 与核验记录；需要课堂练习或用户要求时才增加代表题教师/学生同序双版，避免默认重复产出。用户只要分析或某一版本时按请求缩减。PDF、数值难度、六维统计、变式命题按当次要求增加。

教师版每题完整题干后紧跟答案与解析。学生用途按当次内容合同区分纯题目版、含原本题分析版、完整教师版；不能仅凭“学生版”名称删去用户授权的原分析。本地已有题下分析的分类汇编，未要求去分析时默认沿用含分析版；明确纯题目/无提示请求覆盖，正式考试不套用此默认。恢复本题分析不自动恢复参考答案/参考解析，原分析可能含方法或结果提示，含分析版不能宣称无提示。纯题目版遵守答案隔离；含分析版按授权检查栏目完整性。

用户要求整理成果时，采用交接与产物模板中的成果包规则，按用途区分版本、提供统一入口、保留原文件。

```sh
python3 <本技能目录>/scripts/check_records.py <任务目录>/交接记录.json --check-files
```

默认只向标准输出打印结果；需保存时由执行者指定任务目录中的输出文件。记录格式见交接模板。工具只验证计数、记录与局部来源，不证明数学正确、分类正确或最终页面合格；完整 Markdown 链接、公式、双版和 PDF 的检查由成品技能负责。

有多册覆盖、双版或增量重建时，另用[批次清单合同](references/低返工执行流程.md#批次清单与检查工具)：

```sh
python3 <本技能目录>/scripts/check_batch.py <任务目录>/批次清单.json --check-files
```

它引用原交接记录，不另复制题干；检查母集、覆盖/重叠、题序、依赖版本和指定文件。版本依赖不完整、人工状态或路径存在不能证明内容正确。退出码0为结构及已声明依赖通过，1为错误，2为发现过期产物；脚本不自动重建。

## 验证

技能维护时运行 `scripts/test_check_records.py` 与 `scripts/test_check_batch.py` 的合成不变量测试；结构校验与真实提示词回放分开报告。每批真实交付需记录独立复核、统计复算及成品预览的实际范围。首轮新材料回放未完成前，不宣称稳定迁移。

## 边界

没有学生作答时，只作备课预判，不定型学生。样本覆盖不是下一次考试概率。迁移单元不抬高直接命中频率。待核题不记为零难度。不能把旧案例的分类数量、高频阈值或结论作为新材料的答案。

保留原题、来源与勘误；不自动写回正式题库、不外发、不修改其他技能或长期记忆。新材料尚未实测时明确“迁移效果未验证”。
